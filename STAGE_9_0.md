# Stage 9.0 — Release Baseline

Status: completed as the local release baseline `v0.4.0`.

Stage 9.0 freezes the accepted local-first product through Stage 8.9 before corpus,
storage and worker hardening. It adds no gameplay analytics, tactics, LLM or live
functionality.

## Deliverables

- recoverable source and Git backups created before modification;
- commit `8351d5a` preserves the previously uncommitted Stage 8.2–8.9 source baseline;
- package version `0.4.0` and stable changelog entry;
- cross-platform `uv.lock` generated by `uv 0.11.16`;
- frozen local and Docker dependency installation;
- GitHub Actions quality gate for Python 3.11/Linux and Python 3.13/Windows;
- one local PowerShell release gate shared with CI;
- generated artifacts excluded from Git;
- host-loopback Docker publishing by default;
- explicit release, recovery and security documentation.

## Non-goals

- no cloud deployment;
- no authentication or multi-user support;
- no parser, storage or statistical redesign;
- no public package/container publication;
- no project-license decision on behalf of the owner;
- no Stage 9.1 corpus work.

## Release gate

The release is eligible for tag `v0.4.0` only when the worktree is clean and the shared
gate passes:

```powershell
.\scripts\release_check.ps1
```

CI repeats the gate on Windows and Linux. Integration tests that require a private `.dem`
remain an explicit corpus job and are not silently simulated in public CI.

The final local gate passed on Python 3.13 with 290 tests passing and 6 private-demo
integration tests explicitly deselected. Formatting, lint, strict typing across 179 source
files, dependency consistency, application import, wheel build and Compose validation also
passed. Docker image construction remains a CI gate because Docker Desktop was not running
on the release workstation.
