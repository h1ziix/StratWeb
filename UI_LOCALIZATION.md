# Локализация интерфейса и названия команд

## Версия контракта

- язык интерфейса по умолчанию: `ru`;
- поддерживаемые локали: `ru`, `en`;
- `ui_locale_schema_version`: `3.1.0`;
- хранилище отображаемых названий команд: DuckDB migration `023`.

Stage 9.6.2 использует явный порядок выбора языка: валидный query-параметр `lang`, затем
cookie `stratweb_locale`, затем русский язык по умолчанию. Неподдерживаемое значение не
сохраняется. Переключатель доступен только на полностью переведённой поверхности Tactical V2,
чтобы соседние русские страницы не превращались в смешанный интерфейс.

Stage 9.6.6 добавляет согласованный RU/EN словарь для one-tap coach flow. Сохранённые finding и
recommendation тексты остаются частью версионированного аналитического результата; интерфейс не
переводит и не переписывает их автоматически.

## Граница ответственности

Локализация меняет только представление. События, статистика, evidence, canonical team ID,
fingerprints и версии алгоритмов не переводятся и не переписываются. Технические значения
остаются доступны в сворачиваемых диагностических блоках и JSON API.

Встроенные имена `TeamAlpha` и `TeamBravo` означают только две физические команды матча.
В пользовательском интерфейсе они отображаются нейтрально как «Команда 1» и «Команда 2».
Это не попытка определить настоящее название команды.

## Названия с FACEIT

Проверенные демки FACEIT не содержат надёжного поля с названием вида `team_<ник лидера>`.
Поэтому StratWeb не строит такое название из ника, состава или порядка игроков. Владелец
может указать название вручную на странице матча и при желании сохранить ссылку на страницу
матча FACEIT как источник.

Таблица `team_display_labels` хранит:

- `match_id` и canonical `team_id`;
- отображаемое имя;
- источник `manual` или `faceit_metadata`;
- необязательную ссылку/примечание;
- время обновления.

Отображаемое имя используется в библиотеке, обзоре матча, экономике, профиле соперника и
отчёте. Canonical team identity и доказательные расчёты остаются неизменными. Сброс имени
возвращает нейтральную подпись, а не выдуманное название.

## Правила расширения

Следующие языки должны добавляться через каталог стабильных ключей, без условий по языку в
аналитических сервисах. Динамические сообщения движков следует переводить по типизированному
коду; неизвестный код должен оставаться видимым, а не заменяться догадкой.

Каталоги обязаны содержать одинаковые ключи и одинаковые именованные placeholders. Сейчас это
проверяется для русского и английского при импорте и regression-тестами. Испанский и китайский
не входят в `SUPPORTED_LOCALES`, пока не получат полное покрытие выбранной поверхности.
