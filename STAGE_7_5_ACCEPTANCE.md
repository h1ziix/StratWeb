# Stage 7.5 rework — browser render audit and acceptance candidate

Historical note: the isolated compositor and paint/raster findings remain valid, but
the sample-driven playback clock and stateless nickname placement documented by this
candidate were superseded by
[Stage 7.6](STAGE_7_6_ACCEPTANCE.md). Stage 7.5 frame pacing did not prove that dense
event intervals played at the intended relative-demo-tick speed.

## Status

The first Stage 7.5 submission was rejected after manual testing. Its synthetic
renderer-duration counters did not include browser Layout, Style, Paint, Raster, or
Composite work and therefore understated the real cost. This document supersedes
that report.

The reworked implementation is ready for another manual acceptance pass. Stage 8
has not started.

## Evidence boundary

This rework changes browser presentation and playback scheduling only. Stored
Spatial/Temporal samples, event ticks, run selection, parser output, map projection,
and API evidence contracts are unchanged. Smooth player motion is still
presentation-only and is neither returned by the API nor persisted.

There are no heatmaps, zones, map-control estimates, tactical inference,
recommendations, coaching, AI, or projectile simulation.

## Reproducible browser profile

Both traces use:

- Microsoft Edge/Chromium through the DevTools Protocol;
- viewport 1600 × 1000;
- real FACEIT Overpass match `dba336bb-dc00-5974-bebe-3525d39a6ef4`;
- round 10 from tick 67391;
- Smooth mode at 4× for ten seconds through the mass fight;
- the same `devtools.timeline`, V8 sampling, Blink, compositor, GPU, loading, and
  raster trace categories;
- `Performance.getMetrics`, a DOM `MutationObserver`, frame cadence sampling, console
  and page-error capture.

Trace summaries are generated by
`scripts/analyze_browser_trace.py` without loading the complete trace into memory.

## Root cause analysis

The lag was an accumulation of short browser pipeline work, not one JavaScript long
task:

1. Player movement changed SVG `transform` attributes inside one shared overlay.
   Chromium invalidated and repainted the SVG and often the document on almost every
   callback.
2. SVG filters, drop shadows, effects, and a fixed blurred transport bar enlarged
   the paint/raster surface.
3. Event marker nodes accumulated by event ID. Event chips marked `hidden` were
   nevertheless displayed because the author `.event-chip { display: inline-flex }`
   rule overrode the user-agent hidden presentation. A round-10 playback grew to 176
   visible chips and expanded the document.
4. `history.replaceState` ran for every authoritative sample while playing. CPU
   sampling attributed about 186 ms to it in the baseline trace.
5. Projectile/effect signatures, event rendering, label layout, metrics, status text,
   and URL work were mixed into the visual frame path.
6. The prior square map was constrained by page headers, margins, a 250-pixel
   sidebar, a fixed transport overlay, and content below the map.

The most expensive application function was
`spatial-player.js:frame`: 1,073.7 ms total over the baseline trace, 0.460 ms mean.
The larger browser cost was `Paint`: 2,704.2 ms total, including 2,016.1 ms attributed
to document paint and 381.5 ms to the shared SVG overlay.

## Frame pacing and DOM stability

Headless Chromium exposes an uncapped browser rAF callback rate near 240 Hz; it is
not a monitor FPS figure. The old renderer attempted work on practically all those
callbacks and recorded three intervals over 34 ms.

The final renderer deliberately delivers a 60-FPS presentation budget:

| Pacing metric | Final |
| --- | ---: |
| Delivered transform batches | 602 / 10 s |
| Delivered rate | 60.2 FPS |
| p95 / p99 interval | 17.6 / 18.2 ms |
| Maximum interval | 28.3 ms |
| Intervals above 34 ms | 0 |
| Browser long tasks | 0 |
| Buffering transitions | 0 |
| Console/page errors | 0 |

DOM observations:

| DOM metric | Before | Final |
| --- | ---: | ---: |
| Mutations | 57,747 | 14,693 |
| Added nodes during playback | 3,010 | 0 |
| Removed nodes during playback | 2,105 | 0 |
| Total document nodes after playback | 1,620 | 665 |

The remaining mutations are principally guarded `style.transform`, direction
rotation, opacity/visibility, a five-Hz scrubber update, and exact evidence state
changes.

## Renderer rewrite

The shared moving SVG overlay was removed. The viewer now has isolated layers:

1. static map and static low-opacity workspace backdrop;
2. player compositor layer;
3. projectile compositor layer plus a trail-only canvas;
4. utility-effect layer;
5. bounded exact-event layer;
6. independent HTML label layer;
7. independent selection layer;
8. UI overlays.

All dynamic elements are created before playback:

- 12 player slots;
- 24 projectile slots;
- 32 effect slots;
- 8 event-marker slots;
- 5 current-event ribbon slots;
- one bomb marker and one selection marker.

Slots are deterministically assigned to current evidence. Capacity overflow
contributes to rejected-marker diagnostics instead of creating nodes mid-playback.
Player slots only change transform, view-direction rotation, opacity/visibility, and
rare exact state attributes. A transition plan is constructed once per authoritative
sample pair rather than rebuilding player maps on every visual frame.

Projectile trails use one isolated canvas and redraw only when exact trail evidence
or utility filters change. Event markers and the bounded current-event ribbon update
only when exact event evidence changes. Historical events remain available through
Jump, Temporal UI, and evidence APIs.

URL state is updated on pause, jump, filter change, or navigation—not for every
playing sample. Diagnostics DOM is not touched while the drawer is closed. Visible
scrubber text is throttled to five Hz.

## Product layout and interaction

- The content fills the viewport without document scrolling at 1600 × 1000.
- The sidebar is 196 pixels and contains only Round, Team, Player, Utility, Jump, and
  Playback plus Diagnostics/Fullscreen actions.
- Technical state, buffering, capabilities, run IDs, and counters exist only in the
  Diagnostics drawer.
- The map consumes all available vertical space and is fit with a `ResizeObserver`;
  the square radar is never distorted. A static dimmed radar backdrop turns
  unavoidable widescreen side space into a deliberate workspace.
- Current events are limited to a five-slot ribbon instead of an unbounded page.
- T and CT use distinct shield markers, selection is a separate outline, dead players
  use a translucent cross, and bomb/utility/events have typed glyphs.
- Hidden labels disappear immediately; Medium/Short remain deterministic and
  zoom-aware.
- Auto focus remains optional and disables on manual pointer, wheel, zoom, reset, or
  fit interaction.
- Utility filters hide and restore projectiles, effects, and trail canvas evidence.

## Critical review

- A timer-assisted rAF experiment reduced CPU work but introduced three scheduling
  gaps, including one 113-ms interval. It was rejected; the final code uses pure rAF
  with a 60-FPS transform budget guard.
- A 32-sample network chunk experiment from the first attempt remains rejected
  because it increased request pressure; the bounded size remains 64.
- Fixed pools are intentionally finite. Known CS2 and real FACEIT round-10
  concurrency fit comfortably; overflow is exposed through diagnostics rather than
  causing a runtime allocation.
- A square evidence map cannot fill a 16:10 panel without crop or distortion. The
  implementation maximizes the undistorted radar height and uses a static backdrop
  for the residual horizontal workspace.
- Map revision uncertainty remains visibly warned. Visual polish does not imply
  proven historical map semantics.
- Manual product acceptance remains the user's decision; this report presents a
  retest candidate rather than self-declaring the rejected stage accepted.

## Playback freeze correction

Manual follow-up on 2026-07-26 exposed a state-dependent freeze that the original
profile scenario did not cover:

1. opening a round at its final stored sample made `play()` return immediately while
   the button still said `Play`;
2. far navigation fetched the correct chunk, but eviction was anchored to the old
   index and deleted the requested chunk before it could be selected;
3. unversioned static URLs could leave an already-used browser with incompatible
   HTML and JavaScript revisions.

The controller now treats playback from the final sample as Replay, retains fetched
chunks around the navigation target, identifies the final state explicitly, and uses
file-derived asset versions with mandatory revalidation. Browser verification against
the FACEIT database covers first-to-last navigation, last-to-first Replay, far
scrubbing, Pause stability, and round-10 mass-fight playback. There were no console
errors, page errors, failed requests, or visible error overlays.
